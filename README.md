# Teachable AI 2.0 — Build Status

Next.js 14 (App Router) + Supabase (Postgres/pgvector/Auth/Storage) + Groq, deployed to Vercel. Migrated fully from the previous Firebase + FastAPI/Render + Pinecone stack, per the PRD.

## ✅ What's real and working

- **Foundation** — Tailwind wired to the *exact* 5-theme CSS variable system from the original `style.css` (light/dark/cafe/neon/aqua), so the visual identity is unchanged from the old app.
- **Database** — `supabase/schema.sql`: full relational schema with `pgvector` and **Row Level Security on every table**, so a user can never read/write another user's data. `supabase/storage.sql` locks down the private `documents` bucket the same way. Historical `phase5.sql`/`phase6.sql` scripts are archived under `supabase/archive/`.
- **Auth** — Supabase Auth (email/password + Google OAuth), `middleware.ts` protecting `/dashboard` and `/api/*`.
- **Subjects & Chats** — Each subject supports multiple chats, each with a mode (`tutor / summary / flashcards / practice / quiz / exam`).
- **Document pipeline** — accepts PDF, DOCX, TXT, Markdown, CSV, JPG, PNG, and WebP; stores files in Supabase Storage, extracts text (PDF page extraction, DOCX parsing, or OCR for images), chunks it, embeds **locally via `@xenova/transformers`** (ONNX, no PyTorch or external embedding API cost), and stores vectors in `document_chunks`. Real processing states (`pending/processing/ready/failed`) appear in a file manager panel with per-file status and delete. Image OCR uses Tesseract.js English language data, fetched and cached on first use.
- **RAG + Tutor** — `lib/rag/chat.ts` is the shared multi-mode engine. The "is there enough evidence to answer" judgment is made **by the model itself** via a private marker string, not a pre-LLM heuristic — this matters because an earlier, simpler version of this check was hijacking plain conversational messages ("hi") into the external-search permission flow. Casual chat and off-topic small talk are now handled naturally.
- **Knowledge modes** (PRD §5.7) — `materials_only / ask_before_external / materials_web`, all functional. "Ask Before External" gives a fixed two-choice offer (web search vs. general knowledge) that reliably parses a follow-up reply, since it's generated by our own code rather than left to the model to phrase consistently.
- **External search** — via Groq's built-in `groq/compound` model (web search backed by Tavily, server-side), using the same `GROQ_API_KEY` already configured — no separate Brave/YouTube API keys needed. Rate-limited to 15 searches/day/user, with graceful fallback to general knowledge on failure or exhaustion.
- **Conflict detection** — flags when top-matching chunks come from multiple documents with similarly high relevance and instructs the model to explicitly check them against each other rather than silently picking one.
- **Flashcards** — real generated decks (not chat text) with a flip-card review UI, stored and reloadable.
- **Quiz & Exam** — structured question generation (multiple-choice + short-answer), configurable question count and timer duration, real grading (exact-match for MC, a single batched LLM call for short-answer), a scored results screen with per-question explanations and citations, and an "Explain in Tutor" link per question that switches to the Tutor chat with the question pre-filled for a deeper walkthrough. Regeneration is deliberately randomized and told to avoid repeating prior questions from either mode on the same subject, so Quiz and Exam don't end up drawing identical questions.
- **Progress & targeted review** — Quiz/Exam and Practice results update rolling per-topic strength signals. Students can review progress and launch a Practice chat focused on a selected topic; Tutor/Practice prompts also use weak-topic signals when relevant.
- **Citations** — stored as structured rows (`citations` table), not just embedded in message text. PDFs cite filename and PDF page; other file types cite by filename because they do not provide reliable PDF page numbers. Web and YouTube citations render as clickable source cards.
- **Mobile** — sidebar is a proper off-canvas drawer with a working menu button on small screens.

## Remaining limitations

- **Section extraction is heuristic** — headings are inferred from numbered headings, named section labels, and uppercase lines. PDFs with unusual layout or unmarked headings may still cite only the page.
- **YouTube timestamps depend on search results** — timestamp parameters are preserved in citations and displayed when present, but Groq search does not provide transcript-level timestamps for every video.
- **Summary mode is plain chat** — arguably fine, since summarizing is naturally conversational, but flagging it as a deliberate choice rather than an oversight.

## Setup

For GitHub + Vercel hosting, use the step-by-step [deployment guide](DEPLOYMENT.md).

1. Create a Supabase project. For a fresh install, run `supabase/schema.sql` and then `supabase/storage.sql` in the SQL editor. For an existing project, apply only migrations it has not already received: `supabase/rate_limits.sql` (atomic quotas), `supabase/progress_atomic.sql` (atomic progress updates), `supabase/owned_delete_policies.sql` (owner-scoped deletion), `supabase/section_chunking.sql` (section metadata and vector-search RPC), and `supabase/sample_document_chunks.sql` (bounded generation sampling). Do not rerun the full fresh-install schema on an existing database. Historical phase scripts are in `supabase/archive/`; do not run them on a current install.
2. Enable Google as an OAuth provider in Supabase Auth settings (optional), and set your Site URL / Redirect URL under Authentication → URL Configuration.
3. Copy `.env.example` → `.env.local` and fill in your Supabase + Groq keys. No Brave/YouTube keys needed — web search runs through Groq directly.
4. `npm install && npm run dev`.

## Architecture notes worth knowing

- **Embeddings run in-process**, not via a hosted API — `@xenova/transformers` needs to be excluded from webpack bundling in `next.config.js` (`serverComponentsExternalPackages`), since it ships a native ONNX runtime binary that breaks if webpack tries to bundle it.
- **`pdf-parse` must be imported from its internal lib path**, not the package root — the package's main entry file has debug code that runs on import and tries to read a bundled test PDF from disk, which throws in serverless/Next.js environments.
- **Groq's model lineup has already shifted once during this build** — `llama-3.3-70b-versatile` moved to an Enterprise-only tier mid-project. If a model 404s, check `lib/rag/groq.ts` (`GROQ_MODEL`) and `lib/rag/external.ts` (`SEARCH_MODELS`) first.
